# 로그인 화면 연결 검증 — #233·#234

검사일: 2026-10-29. UI와 app.py 범위에서 화면 연결을 보완했습니다.

## 반영한 내용

- 현재 앱의 `shell.footer_company` 생성과 등록을 확인했습니다.
- `component_contract.validate_component_contract()`는 실제 화면 참조에 필수 키가 있는지, 동일한 컴포넌트가 앱에 등록됐는지, 이벤트 출력 목록에도 포함됐는지 앱 생성 시 검사합니다.
- 키 누락을 `__missing__`으로 자동 생성하는 대역도 `name in refs` 검사로 검출합니다.
- 누락된 경우 로그인 요청 전 앱 생성 단계에서 해당 항목을 포함한 오류를 발생시킵니다. 사용자 입력·비밀번호·세션은 검사에 포함하거나 출력하지 않습니다.

## 로컬에서 확인한 것

프로젝트 `.venv`에서 실제 `build_app()`으로 만든 컴포넌트를 사용한 로컬 회귀 검사 4개가 통과했습니다.

1. demo 서비스: 일반 사용자·회사 관리자·전체 관리자의 로그인, 역할별 메뉴, 비밀번호 입력 초기화, 로그아웃, 잘못된 비밀번호 안내.
2. BackendServices와 실제 create_bindings 연결: 세 역할의 인증 결과를 합성 대역으로 제공하여 로그인 후 화면 전환, 로그아웃, INVALID_CREDENTIALS 안내. 실제 DB 인증 시험은 아닙니다.
3. footer_company를 일부러 삭제: 자동 생성 dict 대역에서도 missing 오류가 발생하고 키가 자동 생성되지 않음.
4. 실제 컴포넌트를 앱 등록 목록 또는 이벤트 출력 목록에서 제외: 해당 연결 오류를 검출.

반환된 화면 변경이 실제 앱의 컴포넌트만 참조하는지도 검사했습니다. 이 로컬 검사는 hyundap/tests/에 추가되지 않았습니다.

## 아직 확인하지 못한 것

- 브라우저 자동화 연결이 unavailable 상태여서 브라우저 로그인·스크린샷 확인을 수행하지 못했습니다.
- 실제 DB 계정으로 인증하여 후속 검색·업로드·다운로드까지 실행하지 않았습니다.
- 이슈가 보고된 test-01 버전과 현재 UI 브랜치는 다릅니다. 위 결과만으로 이슈의 브라우저 완료 조건을 충족했다고 표시하지 않습니다.

## QA 담당자에게 인계할 항목

- 로컬 검사를 hyundap/tests/에 이관하고 실제 build_app() 참조로 유지합니다.
- 필수 참조를 일부러 제거한 변형이 실패하는지 확인합니다.
- 세 역할의 demo 검사와 실제 backend DB 인증 검사를 구분합니다.
- 실제 브라우저에서 성공·실패·로그아웃 후 화면 상태를 확인하고 커밋·실행 명령·환경을 기록합니다.
