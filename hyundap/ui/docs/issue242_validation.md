# #242 상단바 화면 전환 보완 검증

검사일: 2026-10-29. UI 및 app.py만 수정했습니다.

## 코드에서 확인한 구조와 변경

기존 관리자 색상은 헤더 내부 data-role 요소에 의존했고 메뉴 전환에서는 계정 HTML과 버튼의 표시값을 다시 지정하지 않았습니다. 이 구조만으로 신고된 브라우저 현상의 원인이 확정되는 것은 아닙니다.

- 로그인 및 메뉴 전환 시 검증된 사용자로 공통 화면의 역할 클래스·계정 HTML·메뉴 이름·선택 상태·로그아웃 표시를 함께 갱신합니다.
- 관리자 강조색은 공통 화면의 역할 클래스로 결정하여 헤더 HTML 내부의 요소 존재 여부에 의존하지 않습니다.
- 메뉴 버튼의 표시명·스타일 클래스·노출 여부도 함께 갱신합니다.
- 로그아웃 시 역할 클래스를 초기화합니다. 표시용 역할 클래스는 백엔드 권한 검사에 사용하지 않습니다.

## 확인한 것

가상환경에서 실제 build_app(mode="demo") 컴포넌트를 사용하는 로컬 검사 3개가 통과했습니다.

1. 회사 관리자와 전체 관리자가 검색→업로드→검색을 반복할 때 계정·관리자 역할 클래스·메뉴 이름·로그아웃 표시·선택 메뉴가 유지됩니다. 앞선 화면 표시가 비워진 상황에서도 다음 이동 패치가 복원합니다.
2. 일반 사용자는 일반 사용자 역할을 유지하며 업로드 메뉴를 숨기고 직접 업로드 이동도 거부합니다.
3. 세션 재검증이 반환한 역할·표시명이 바뀌면 이전 로그인 정보가 아니라 최신 정보를 표시합니다.

기존 UI 컨트롤러·백엔드 연결·서비스·답변 표시 검사 51개도 통과했습니다. 신규 검사는 로컬 파일로 실행했으며 hyundap/tests/에 추가하지 않았습니다.

## 남은 검증

브라우저 접근 호스트가 unavailable 상태여서 신고된 화면의 재현·스크린샷·실제 계산된 CSS 색상은 확인하지 못했습니다. 실제 DB 인증을 사용한 화면도 검증하지 않았습니다. 브라우저에서 관리자 로그인→업로드→검색 반복 후 상단바·계정·로그아웃이 유지되는지 추가 확인해야 합니다.
