## 재현하고 수정한 문제

### #243 — 로그인 화면 갱신 실패 후 세션 잔류

실제 `build_app(mode="demo")`로 만든 앱에서 헤더 렌더링에 예외를 주입했다. 수정 전에는 `ctx.user`가 남고 logout 호출이 없었다. 수정 후에는 로그인 화면 갱신값을 모두 만든 뒤에만 `ctx.user`를 설정하며, 실패 시 발급받은 세션으로 logout을 호출한다.

- 화면 갱신 실패와 필수 컴포넌트 누락: 로컬 로그인 상태를 확정하지 않고 발급 세션 정리.
- 이전 로그인 응답이 늦게 도착하거나 요청이 취소됨: 해당 후보 세션만 정리하고 새 정상 세션은 보존.
- 인증 후 UI 어댑터의 필수 필드 검증·회사 권한 확인 실패: 컨트롤러가 받지 못한 세션도 `BackendServices.login`에서 정리.
- 정상 인증과 자격 증명 거절 경로: 불필요한 logout 호출 없음.
- logout 자체가 실패하면 원래 오류와 미확정 로컬 상태를 유지하고 예외 종류만 로그에 기록한다. 이 경우 서버 세션 폐기 성공을 보장하지 않는다.

### #239 — 빠른 요약 delta/reset 누락

이전에는 공유 작업 상태를 0.2초마다 읽어 그 사이에 도착한 중간 문장·초기화를 놓쳤다. 활성 화면마다 큐를 등록하고 각 이벤트의 스냅샷을 순서대로 전달하도록 변경했다. 0.2초 타임아웃은 화면 요청이 무효화되었는지 확인하는 용도로만 사용한다.

- `delta → reset → delta → done`을 지연 없이 발생시켜도 각 내용이 순서대로 전달됨.
- 문서 선택 변경 시 표시 구독만 제거. 시작한 요약은 계속하고 같은 문서·버전으로 돌아오면 최신 진행 내용/완료 결과 표시.
- 요약 버튼을 눌렀을 때만 시작하며, 진행 중 중복 호출 방지·오류 후 복구·로그아웃 정리 유지.
- 사용자 요청에 따라 기존 공용 `summary_lock`과 대기 정책은 변경하지 않았다. 사용자 간 요약 대기가 생길 수 있다는 #239의 별도 정책 문제는 남아 있다.

### 최신 develop 테스트의 남은 기대값 차이

원본 `test_delta_accumulates_and_reset_clears`의 기대값:

```python
['', '첫 줄\n', '', '새 줄\n', '최종 요약 [1]']
```

수정 후 실제 표시값:

```python
['요약 중입니다.', '첫 줄\n', '요약 중입니다.', '새 줄\n', '최종 요약 [1]']
```

중간 문장과 초기화 이벤트는 이제 누락되지 않는다. 시작과 reset 시에는 현재 디자인 요구에 맞춰 본문에 `요약 중입니다.`를 표시하므로 원본 테스트의 빈 문자열 기대값과 다르다. 담당자에게 기대 표시값 갱신을 요청해야 하며, 이 원본 검사를 통과했다고 보고하지 않는다. 원격 테스트와 다른 develop 소스 전체를 병합한 통합 검사도 수행하지 않았다.

