## 1. 개선 이슈 목록

우선순위는 시연·제출에 미치는 영향을 기준으로 정했습니다.

- **높음**: 시연 중 사용자가 겪을 수 있는 문제
- **보통**: 품질 개선
- **낮음**: 내부 구조 정리

## 2. KPT 회고 (초안)

각 항목의 근거는 GitHub 기록과 테스트 문서에서 찾은 사례입니다. 팀 회고 시간에 항목을 더하거나 고칩니다.

### Keep — 계속할 점

| 항목 | 근거 사례 |
|---|---|
| 모든 변경을 PR과 리뷰 승인으로 병합 | `develop`은 리뷰 승인 1건이 있어야 병합됨. 리뷰에서 테스트 실패(PR #184), 다른 기능을 멈추게 하는 대기 문제(PR #214)를 병합 전에 발견해 수정함 |
| 폴더 담당 규칙 | 각자 담당 폴더만 수정하고, 다른 폴더 변경은 이슈와 리뷰로 요청함(예: N2·#198은 ingest 담당에게 이슈로 전달). 변경마다 책임자가 분명했음 |
| 자동 실행기로 기능 점검 | 기능 점검 43건을 스크립트(`run_qa.py`)로 만들어, PR 병합 후 같은 조건으로 다시 실행함(10/27과 10/28 모두 41/43) |
| 근거 없는 답변 차단 | 답변·요약의 모든 문장에 출처 표기를 요구하고, 표기가 없는 문장은 화면에 내보내지 않음 |

### Problem — 문제였던 점

| 항목 | 근거 사례 |
|---|---|
| 공유 자원 변경이 미리 알려지지 않음 | 10/27 15:29에 공유 DB가 초기화되어 기존 테스트 계정이 사라짐. 10/28에는 공유 드라이브의 목업 폴더 위치가 바뀌어 기능 점검이 바로 멈춤 |
| PR 병합 전에 이슈가 닫힘 | #181(잘못된 비밀번호 안내)이 10/27에 해결 완료로 닫혔으나, 실제 수정은 10/28에 병합된 PR #184에 있었음 |
| 실제 외부 서비스로 확인한 범위가 좁음 | API 키가 없는 환경에서는 OpenAI 호출을 대역으로만 확인함(PR #214 등). 개인 PC에 MySQL이 없으면 DB 테스트 85개가 실행되지 않음 |
| 기획 문서와 실제 일정·구현의 차이 | README 일정표(10/21~10/28)와 WBS(Day 8 = 11/02)가 달랐고, 요약 형식(표 카드)도 구현과 달라 6.1.3에서 README를 다시 씀 |
| PR 본문이 비어 있거나 테스트가 빠짐 | 관련 이슈가 `close #`로 비어 있는 PR(#202, #214), 테스트 없이 올라온 화면 PR(#215)이 있었음 |

### Try — 시도할 점

| 항목 | 내용 |
|---|---|
| 공유 자원 변경 공지 | 공유 DB 초기화, 공유 드라이브 폴더 이동은 하기 전에 팀 채널에 알리고, 관련 설정(`corpus.json` 등)을 함께 고침 |
| 이슈는 PR로 닫기 | PR 본문에 `close #번호`를 적어 병합될 때 이슈가 자동으로 닫히게 함. 직접 닫을 때는 병합된 PR 번호를 댓글로 남김 |
| 통합 확인 담당과 체크리스트 | 실제 OpenAI·MySQL로 확인할 항목(요약 스트리밍, 업로드 전체 흐름, 권한)을 목록으로 만들고, 키와 DB 접속이 있는 사람이 병합 후 확인함 |
| PR 템플릿 지키기 | 관련 이슈, 실행한 테스트 명령과 결과, 화면 변경 시 스크린샷을 빠짐없이 적음 |
