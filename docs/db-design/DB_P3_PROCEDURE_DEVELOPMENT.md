# 회사별 DB 프로시저 개발 현황

`test-01`에서 이전 Railway 분리 DB 시험 결과를 바탕으로 회사별 계정 준비와 인증·라우팅 프로시저를 개발했다. `HYUNDAP_DB_COMPANY_ACCOUNTS=1`을 명시하면 회사별 계정 시험 경로를 사용한다. 기본값은 기존 공통 계정 방식이다.

## 구현

- `company_admin.create_company_db_user`: 회사 DB를 검증하고, 회사별 MySQL 계정을 잠긴 상태로 생성한다. 업무 테이블에만 DML을 부여하고 회사 정보·소속 표는 읽기로 제한한다. 로컬 설정 저장 뒤 잠금을 풀고 실제 계정으로 소속과 공통 사용자 테이블 접근 거부를 검사한다. 검사 실패 시 계정을 다시 잠그며, 잠금 복구에 실패하면 `RECOVERY_REQUIRED`를 반환한다.
- 운영자 CLI의 `--create-company-account COMPANY_ID`: 준비된 회사의 전용 계정을 생성한다. 회사별 계정 시험 모드에서 신규 회사 등록을 실행하면 회사 전용 계정이 준비된 뒤 회사가 활성화된다. 기본 모드의 기존 동작은 유지한다.
- `company_credentials`: 회사별 MySQL 계정명과 비밀번호를 Git 제외 `.env.company-databases.json`에 저장하고 읽는다. 손상된 파일과 기존 회사 설정 덮어쓰기를 거부한다. 이 파일은 평문 비밀번호를 포함하는 시험용 설정이며, 여러 운영자 프로세스의 동시 쓰기는 지원하지 않는다.
- `company_routines.procedure_statements`: 회사별 인증·라우팅 등록·라우팅 조회·회사 잠금 프로시저와 회사 정보 조회 뷰를 생성한다. 인증은 회사 관리자·직원과 플랫폼 관리자, 세션·사용자·회사 활성 상태를 검사한다. 라우팅은 회사 DB의 문서·버전·작업 관계가 실제 일치하는 경우만 등록한다.
- `authenticate_company_actor`, `register_company_route`: 같은 트랜잭션에서 프로시저를 호출하고 허용된 오류 코드만 반환한다. SQL 원문과 접속 정보는 오류에 노출하지 않는다.

## 검증

- 별도 Railway 시험용 MySQL 8.4.13의 실제 v4 회사 DB 두 곳: 회사 관리자·플랫폼 관리자 허용, 타사 관리자 거부, 존재하지 않거나 서로 맞지 않는 라우팅 거부, 정상 라우팅 및 회사 DB·공통 DB 공동 롤백 성공.
- 같은 시험 환경에서 새 회사를 추가해 전용 MySQL 계정 생성, 로컬 계정 설정 저장, 관리자·플랫폼 관리자 인증, 공통 사용자 테이블 직접 조회 거부, 위조 라우팅 거부를 확인했다. 보완된 계정 활성화 후 검증을 포함해 재실행했다.
- 실제 새 계정 연결에서 Python 호출 함수의 인증, 잘못된 라우팅의 `INVALID_STATE`, 정상 라우팅 및 공동 롤백을 확인했다.
- 두 회사의 실제 Railway 시험 DB에서 회사별 계정으로 업로드·게시·상세·버전 이력과 플랫폼 관리자 접근을 확인했다. 타사 접근과 공통 인증 테이블 직접 조회를 거부했다. 수집과 임베딩은 대역을 사용했다.
- 최종 권한 축소 후 별도 Railway 시험 DB에서 신규 회사 자동 계정 생성, 공통 사용자 직접 조회 거부와 계정별 업로드·상세 조회를 다시 확인했다. 수집·임베딩은 대역을 사용했다.
- 별도 로컬 MySQL 8.4.13을 사용한 전체 회귀: 545개 실행, 성공 459개, 건너뜀 86개. 신규 회사 자동 계정 생성, 저장 실패 시 회사 비활성·계정 잠금, 두 회사 계정 접근, 회사 정보·소속 표 갱신 거부, 읽기·쓰기 인증의 잠금 차이를 포함한다. 다른 격리 DB 환경이 필요한 테스트 등은 건너뛰었다.

## 아직 연결되지 않은 범위

기존 공유 Railway DB나 기본 `.env`는 자동 전환하지 않았다. 회사별 시험 모드를 사용하려면 새 공통 DB와 회사별 계정 설정이 필요하며, 기존 공통 계정 회사들을 새 계정 방식으로 자동 이행하지 않는다. 브라우저에서의 실제 업로드·검색과 실제 임베딩·벡터 저장은 시험하지 않았다.

Railway의 별도 v4 시험 스키마에는 개발 중 생성한 시험 회사·계정·합성 문서가 남아 있다. 합성 문서는 메모리 벡터 대역으로 게시했으므로 실제 Chroma에서 검색할 수 없다. 기존 공유 Railway DB의 업무 문서는 변경하지 않았다.

시험 모드는 `HYUNDAP_DB_LAYOUT=split`과 `HYUNDAP_DB_COMPANY_ACCOUNTS=1`을 프로세스 시작 전에 지정한다. 선택적으로 `HYUNDAP_COMPANY_CREDENTIALS_FILE`로 별도 파일을 지정할 수 있으며, 이 경우에도 비밀 파일은 반드시 Git에서 제외해야 한다. 설정 오류는 기존 공유 계정으로 자동 전환하지 않는다. 설정 변경 후 앱을 재시작한다.

프로시저의 DEFINER는 실행한 운영자 계정이다. 운영 적용 전 DEFINER 최소 권한, 연결 경로별 `USER()` 신원 보장, 플랫폼 관리자 다회사 전체 흐름, 동시 권한 변경·실패 복구, 인증 오류 계약과 실제 업로드·검색을 추가 검증해야 한다. 회사별 뷰는 제한 계정의 테이블 검증에서 제외하므로, 뷰·프로시저 정의의 변조를 시작 시 전체 검증하는 기능은 아직 없다. 계정 생성 실패 시 DDL은 롤백되지 않으며 부분 객체와 잠긴 계정이 남을 수 있다.
