# DB P2-03 원본 저장·버전 연결 — #205

## 현재 구조와 이슈 문구 정정

2026-10-28, feature/db의 `9590829`에서 db-p2-03을 분기했다.
#205의 documents.storage_key 및 최초 원본 포인터 설명은 과거 구조다.
현재 v4에는 해당 컬럼이 없고 원본 정보는 document_versions.storage_path/sha256/file_size에만 있다.
이를 복원하지 않는다. 첫 버전의 파일도 다른 버전과 동일하게 보존한다.
documents.active_version_id는 공개 버전 선택이며 파일 경로가 아니다.

## 저장 흐름과 책임

| 함수 | 역할 | 처리 |
|---|---|---|
| upload_document | 메인 | 권한 확인 → 파일 준비 → 후보 TX → 원본 복사 → 처리/게시 |
| prepare_upload_source | 보조 | 서버 파일 해시·크기 계산. 클라이언트 경로/해시 값을 저장 기준으로 사용하지 않음 |
| create_upload_candidate | 보조 | 문서·버전·작업과 최종 경로·저장 루트를 같은 TX에서 확정 |
| source_destination | 보조 | 회사/문서/버전/source.확장자로 경로 구성 |
| copy_original | 보조 | 임시 파일 복사·해시 재검사·hard link 공개. 기존 파일을 덮지 않음 |
| resolve_stored_source | 신규 보조 | 절대 경로·링크 해석 후 루트 내부 여부 검사 |
| read_attempt_source | 보조 | DB 읽기 종료 후 경로·파일 해시·크기 검증 |
| retry_upload | 메인 | 같은 버전·작업 재시도, 저장 원본 우선 사용 |

모두 upload_service 모듈의 일반 함수이며 새 클래스는 없다.
스키마·상세 응답·게시/복구 알고리즘은 바꾸지 않는다.

## 보완한 동작

기존 retry_upload는 source_path를 주면 저장 원본이 있어도 copy_original을 호출하여
FileExistsError로 실패했다. 이제 저장 원본이 있으면 재공급 경로를 사용하지 않는다.
저장된 파일이 변조되었더라도 덮지 않고 후속 해시·크기 검사로 거부한다.

기존 read_attempt_source는 DB의 경로를 바로 열었다. 이제 해당 작업의 _upload_root와
함께 검사한다. retry_upload도 같은 경로 검사 함수를 사용한다. 상대 경로·루트 밖 링크는
INVALID_STATE, 저장 원본 없음·읽기 권한 없음은 FILE_UNAVAILABLE, 해시·크기 불일치는
CONFLICT다. 다른 OS 저장 오류는 기존 PROCESSING_FAILED 정책을 유지한다.

원본 재공급도 저장 원본이 없을 때만 수행하고 저장 당시 해시·크기와 일치해야 한다.
실패한 후보·작업은 남겨 같은 ID로 재시도하며 이전 공개 버전·원본을 삭제하지 않는다.
후보 저장 TX가 실패하면 후보·작업·신규 문서가 롤백되고 파일 복사를 시작하지 않는다.
파일 복사 후 실패는 DB와 파일을 하나의 원자적 트랜잭션으로 취급하지 않으며 실패 원본을 보존한다.

## 보존 범위와 한계

파일 해시 계산·resolve·복사는 모두 DB TX 밖에서 수행한다. 실제 외부 수집/벡터 동작도
DB 잠금을 유지하지 않는 기존 순서를 따른다. 상세 및 관리자 이력 응답에는 내부 경로가 없다.
검사는 애플리케이션이 관리하는 저장 루트를 전제로 하며, 권한 있는 외부 프로세스가 검사와
파일 열기 사이에 파일/링크를 교체하는 OS 수준 경쟁까지 원자적으로 차단하는 기능은 아니다.
다운로드·미리보기·원본 삭제·재색인 관리 기능은 추가하지 않는다.

## 검증 구성

test_original_storage: 임시 파일에서 기존 원본 덮어쓰기 거부, 해시 불일치와 권한 오류 시
임시 파일 정리, 상대/루트 밖/링크 경로 거부를 검사한다. Windows에서 실제 링크 생성이
허용되지 않으면 resolve 결과 대역으로 경계 판정만 검증하며 실제 링크 검증과 구분한다.

test_upload_workflow: 격리 MySQL에서 저장 원본 우선 재시도, 파일 없음/권한 오류/루트 밖 경로,
두 버전 원본 보존과 중복 거부, 후보 DB 기록 실패의 원자성을 추가 검증한다.
기존 실패 후 재시도·게시 복구·포인터 보호·외부 작업 중 잠금 해제 회귀도 전체 실행에 포함한다.

실행: 새 로컬 MySQL 8.4.13과 빈 전용 DB 5개, 임시 파일 및 벡터/수집 대역.
명령: `python -m unittest discover -s hyundap/tests -t .`.
Railway와 실제 외부 API에는 접속하지 않았다.
