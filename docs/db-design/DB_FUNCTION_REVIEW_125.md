# DB 함수 125개 전수 점검 — 반복·분기·중복 처리

검토일: 2026-10-28 · 브랜치: `db-p3-test` · HEAD: `ee77c11`

**Python 파일 16개에 정의된 함수·메서드 125개를 모두 검토했다. 유지 104개, 개선 21개이며, 개선 작업은 17개 묶음이다. 이번 작업은 검토와 기록만 수행했으며 구현 코드는 수정하지 않았다.**

## 범위와 집계 방식

현재 작업 트리의 미커밋 회사별 DB 분리 구현과 학습 중심 리팩토링을 포함한다. HEAD의 커밋 내용만 검토한 결과가 아니다. 이전 [학습 중심 리팩토링 보고서](DB_LEARNING_REFACTOR_REPORT.md)의 결과를 덮어쓰지 않고 별도 점검으로 기록한다.

`hyundap/db/**/*.py`를 AST로 열거했다. 모듈 수준 함수 123개, `DbError.__init__` 메서드 1개, `ingest_and_save_chunks.find_by_hash` 내부 함수 1개를 합해 125개다. import한 함수와 데코레이터가 실행 중 만드는 함수는 세지 않았다. `__init__.py`는 파일 검토에 포함하지만 함수가 없어 함수 표에는 별도 행이 없다.

각 함수의 전체 본문을 읽었고, 중복 제거 후보는 호출부·입력 검증·반환값·오류 처리와 대조했다. 관련 테스트 소스도 확인했다. **이번에는 실행 테스트, DB 접속, Railway 변경, 외부 API 호출을 하지 않았다.** 아래 테스트 항목은 개선 적용 후의 검증 계획이지 이번 실행 결과가 아니다.

## 동일하게 적용한 판단 기준

1. 같은 입력을 같은 목적으로 두 번 순회하거나 변환하는가? 한 번으로 합쳐도 원본 보존과 오류 계약이 유지되는가?
2. 동일 조건을 반복하거나 앞선 검증 때문에 도달할 수 없는 분기가 있는가? 서로 다른 업무 조건까지 긴 `or` 한 줄로 합치지는 않는다.
3. 상위 함수의 값 검증을 내부 함수에서 그대로 반복하는가? 공개 진입점의 검증과 독립 호출이 가능한 보조 함수의 검증은 보존한다.
4. 같은 시점의 정보를 반복 조회하는가? 잠금 획득 후, 외부 작업 후, 회사 활성 상태 변경을 감지하는 재조회는 별도로 판단한다.
5. 기본 `if`·`for`·사전·집합으로 더 명확해지는가? 줄 수를 줄이기 위한 내포식, 새로운 클래스, 범용 처리기 도입은 선정 근거로 삼지 않는다.

`유지`는 이 기준에서 변경 이점이 뚜렷하지 않다는 뜻이다. 모든 기능의 무결함이나 모든 화면 연결 완료를 뜻하지 않는다. `개선`은 구체적인 단순화 후보가 있다는 뜻이며 변경·검증 완료를 뜻하지 않는다.

## 적용할 때의 검증 순서

1. **함수 내부 단순화부터 한 작업씩 적용한다.** G01~G10 중 1차 항목과 G14·G17은 입력/반환/오류 코드 비교 후 관련 회귀를 확인한다. G04의 두 함수는 전달 인자를 함께 변경하는 하나의 작업이다.
2. **스키마 재사용·회사 일괄 조회·존재 조회는 각각 따로 적용한다.** G11~G13은 격리 MySQL에서 구조 위반 검출, 회사 경계, 원자성, 쿼리 결과를 확인한다. 조회 수 감소는 실제 SQL 이벤트 계측으로 별도 확인해야 하며 이번 보고서에서 속도 향상 수치를 주장하지 않는다.
3. **작은 변환 정리는 마지막에 적용한다.** G15~G16은 URL 처리와 표현식 경계 회귀를 확인한다. 단순 줄 수 감소를 위해 앞선 작업에 불필요하게 섞지 않는다.
4. **전체 작업 후 단일/분리 모드를 함께 회귀한다.** DB 격리 설정을 사용하고 원본 보존·현재 권한·회사 격리·게시 경쟁·복구·오류 비노출을 포함한다. 자동으로 운영 DB에 연결하거나 실제 임베딩 API를 호출하지 않는다.

## 기록 자체의 검증

AST에서 얻은 `(모듈, 전체 함수명, 시작 줄)` 목록과 위 001~125 원장을 비교한다. 누락·중복·추가 함수가 없는지, 판정 값이 유지/개선 중 하나인지, 파일별 합계와 작업 묶음의 대상 번호가 맞는지 검사한다. 시작 시 수집한 16개 Python 파일의 SHA-256과 완료 시 값을 비교해 검토 중 구현이 변경되지 않았는지도 확인한다.

기록 검증 실행 결과:

| 확인 항목 | 결과 |
| --- | --- |
| 함수 정의와 원장 대조 | 125/125 일치, 누락 0, 중복 0, 시작 줄 불일치 0 |
| 판정·개선 작업 연결 | 유지 104, 개선 21, 작업 17개와 대상 함수 연결 일치 |
| 파일별 집계 | 16/16 일치 |
| 검토 전후 Python 파일 해시 | 16/16 동일, 구현 변경 0 |
| 문서 인코딩 | UTF-8 읽기 성공, 대체 문자·연속 물음표 없음 |

이 검증은 문서의 범위·집계·소스 보존 확인이다. 실행 동작에 대한 단위/통합 테스트 통과를 뜻하지 않는다.

검토 대상 코드의 합성 SHA-256은 다음과 같다. 파일 경로 정렬 순서로 각 UTF-8 상대 경로와 해당 파일 SHA-256 바이트를 이어 해시한 값이다. 문서 자체는 이 코드 해시에 포함하지 않는다.

```text
84192bfcc699abc3a49e187cef8dead9f067395b636c922ab185eb964310158f
```

이 결과는 현재 작업 트리의 정적 검토다. 향후 코드를 바꾸면 함수 시작 줄과 해시를 갱신하거나 새로운 검토 기준을 명시해야 한다. 기존 실행 테스트 기록을 이번 결과로 재사용하지 않는다.
