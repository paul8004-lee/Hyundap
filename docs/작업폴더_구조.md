# 현답 작업 폴더 구조

작업 폴더는 기획안 ver2의 역할 분담에 맞춰 기능 폴더 7개와 테스트 폴더 1개로 나눕니다. 한 폴더는 한 사람이 책임지고, 다른 폴더의 기능은 함수 호출로만 씁니다.

폴더마다 담당자를 적었습니다. `(예정)`은 아직 만들지 않은 파일이며, 파일 이름은 담당자가 자신의 폴더 안에서 바꿀 수 있습니다. 폴더마다 `docs/spec.md`에 그 폴더의 명세가 있습니다.

```text

├── requirements.txt            # 패키지 목록 (앱·DB 전체) · 이성민
├── MYSQL_ACCESS.md             # 팀 MySQL 접속 방법 · 전재경
├── .env                        # API 키·DB 주소 (git 제외, 각자 만듦)
│
├── docs/                       # 팀 문서
│   ├── spec.md                 #   통합 기능명세서 · 이성민(관리)
│   ├── 작업폴더_구조.md        #   이 문서
│   ├── 기능_흐름도.png
│   ├── diagrams/               #   기능별 흐름도
│   └── db-design/              #   DB 계약·스키마·마이그레이션 · 전재경
│

    │   └── schemas.py          #   Section, CommonDocument, Chunk, make_chunk_id, DOC_TYPES
    │

    │   ├── mock_services.py    #   화면 개발용 예시 데이터

    │   ├── validator.py        #   형식·100MiB·손상·암호화·중복 검증
```

## 폴더 규칙

- 자기 폴더 안의 파일만 고칩니다. 다른 폴더의 기능이 필요하면 그 폴더의 함수를 호출합니다.
- common/ 에는 여러 폴더가 함께 만들고 쓰는 형식만 둡니다. 바꾸기 전에 팀에 알리고, 관리자(이성민)가 반영합니다. 한 폴더만 쓰는 형식은 그 폴더에 둡니다 (예: chatbot 결과 형식 → `chatbot/models.py`).
- 문서 유형은 `common.schemas.DOC_TYPES`(manual·policy·guide·other) 하나만 씁니다. 회사 목록은 DB와 auth가 제공하므로 코드에 적지 않습니다.
- 코드 주석과 설명(docstring)은 한글로 씁니다.
- data/ 와 .env 는 git에 올리지 않습니다.
- Day 5(10/28)에 각 폴더를 develop에 merge하고 Day 6부터 tests/ 로 통합 테스트를 진행합니다.

## import 규칙과 실행 방법

| 상황 | 쓰는 법 |
|---|---|
| 다른 폴더 기능 | `from hyundap.common.config import get_settings` |
| 같은 폴더 안 파일 | `from .models import IngestError` |
| 쓰지 않기 | `from common...`처럼 `hyundap.` 없는 형태, `sys.path` 조작 |

모든 명령은 저장소 맨 위(`Hyundap/`)에서 실행합니다.

```bash
pip install -r requirements.txt                       # 패키지 설치
python -m hyundap.app                                 # 앱 실행
python -m unittest discover -s hyundap/tests -t .     # 전체 테스트
python -m hyundap.db.connection                       # DB 연결 점검
```

DB 통합 테스트는 전용 테스트 DB 주소(`DB_MIGRATION_TEST_URL` 등)가 없으면 건너뜁니다. 자세한 내용은 `hyundap/db/docs/spec.md`를 봅니다.
