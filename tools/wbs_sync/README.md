# WBS → GitHub 이슈 동기화

팀 WBS 엑셀을 기준으로 GitHub 이슈와 마일스톤을 만들고 갱신하는 스크립트입니다. **WBS가 유일한 기준**이며, 방향은 엑셀 → GitHub 한쪽입니다.

## 처음 한 번만

1. GitHub CLI 로그인: `gh auth login`
2. 엑셀 라이브러리 설치: `pip install openpyxl`

## 사용법

1. WBS 파일을 준비합니다. 스크립트는 아래 순서로 파일을 찾습니다.
   1. `--file "경로/파일.xlsx"` 로 직접 지정한 파일
   2. **Google Drive 데스크톱 앱**에 연결된 팀 폴더의 `다중기업문서검색플랫폼_WBS.xlsx` (권장)
      - 내 드라이브에 팀 폴더 `1차 프로젝트_3팀` 바로가기를 추가해 두면, 매번 내려받지 않아도 항상 최신 WBS를 읽습니다.
      - 드라이브 문자(G: 등)와 상관없이 찾습니다. 폴더 ID와 파일명은 `config.json` 의 `drive` 항목에 있습니다.
   3. 레포 폴더(최상위)에 내려받은 `*WBS*.xlsx` 중 가장 최근 파일 (엑셀 파일은 git에 올라가지 않습니다)
2. 미리보기로 바뀔 내용을 확인합니다. 첫 줄에 어떤 WBS 파일을 읽었는지 나옵니다. 이 단계에서는 GitHub가 바뀌지 않습니다.

   ```bash
   python tools/wbs_sync/wbs_sync.py
   ```

3. 내용이 맞으면 반영합니다.

   ```bash
   python tools/wbs_sync/wbs_sync.py --apply
   ```


## WBS → 이슈 규칙

| WBS | GitHub |
|---|---|
| 작업 ID + 작업명 (예: 3.2.1.) | 이슈 제목 `[3.2.1] 작업명`, 본문에 숨은 표식으로 연결 |
| 유형 (로직·화면·문서) | `유형:로직` 등 라벨 |
| 단계 (3.2.0. 형식별 로더 등) | `area:` 분야 라벨 (`config.json` 의 `step_area`) |
| 담당자 이름 | 이슈 담당자 (`config.json` 의 `members`) |
| 담당자 `공통` | `공통` 라벨, 담당자 비움 |
| 담당자 빈칸·`DB` 등 명단에 없는 값 | `담당 미정` 라벨, 담당자 비움 |
| 종료일 | 해당 Day 마일스톤 (`Day N · 월/일`) |
| 상태 `done` | 이슈 닫힘 (완료) |
| 상태 `진행중` | `진행중` 라벨 |
| 행 삭제 | 이슈 닫힘 (계획 변경), 다시 추가하면 다시 열림 |

## 주의

- 자동 관리되는 이슈의 제목·본문·담당자·마일스톤·위 라벨을 GitHub에서 직접 고치면 다음 동기화 때 WBS 내용으로 덮어써집니다. 이슈 댓글과 그 외 라벨(`bug` 등)은 유지됩니다.
- 레포 초대를 수락하지 않은 계정은 담당자로 지정할 수 없습니다. 수락 후 다시 동기화하면 지정됩니다.
- 팀원이 바뀌면 `config.json` 의 `members` 에 `"이름": "GitHub 아이디"` 를 추가합니다.
- WBS의 열 구성(Procedures·Tasks·담당자·schedule·상태·산출물/비고 머리글, Day 행)을 바꾸면 스크립트가 파일을 읽지 못할 수 있습니다.
